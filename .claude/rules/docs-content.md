# ドキュメント記載内容ガイド

各ファイルの役割と記載すべき内容の対応表。「この情報はどこに書くか？」の判断に使う。

| ファイル | 役割 | 記載する内容 |
|---------|------|------------|
| `product-requirements.md` | 何を作るか | プロダクト概要・対象ユーザー・エージェントの責務範囲・機能要件・ユーザーストーリー・受け入れ条件・非機能要件（レイテンシ・コスト・ハルシネーション許容度）・技術制約・スコープ外 |
| `functional-design.md` | どう動くか（ユーザー視点） | 画面構成・ワイヤフレーム・機能詳細・API仕様・データモデル（ER図） |
| `architecture.md` | どう作るか | システム構成図・テクノロジースタック・LLM 基盤レイヤ・アーキテクチャパターン・通信方式・環境変数・観測性 |
| `agent-design.md` | エージェント自身の設計 | エージェント構成・システムプロンプト・ツールカタログ・メモリ/コンテキスト戦略・会話ライフサイクル・モデル選定・ストリーミング契約・コスト/レイテンシ予算・ガードレール |
| `repository-structure.md` | どこに置くか | ディレクトリツリー・配置ルール（`prompts/` `tools/` `evaluations/` 等を含む） |
| `development-guidelines.md` | どう書くか | コーディング規約・命名規則・プロンプト/ツール開発規約・環境変数管理・セキュリティ（コミット・PR 規約は `.claude/skills/workflow-conventions.md`、ブランチ戦略は `.claude/skills/workflow-config.md` で管理） |
| `testing-guidelines.md` | どうテストするか | テスト基本方針・テスト戦略（単体/結合/評価/手動）・評価データセット/指標・テストコード記述ルール・実行コマンド |
| `glossary.md` | 用語の定義 | ドメイン用語・AI エージェント用語・技術用語（日本語・英語・コード命名の対応表） |

## 判断基準

- **新しいドキュメントを作らない** — 上記 8 ファイルのいずれかに該当する情報は、そのファイルに追記する
- **エージェント内部設計は `agent-design.md`** — プロンプト・ツール・メモリ・モデル設定・ガードレールはここに集約する
- **ユーザー視点の動作仕様は `functional-design.md`** — 画面・API・データモデルなど「ユーザーから見た動作」はここに集約する
- **両者が混ざる場合** — `functional-design.md` には概要のみ書き、詳細は `agent-design.md` に記載してクロスリファレンスを張る
- **各ファイルにはテンプレート（TODOコメント付き）が用意されている** — 新規記載時はテンプレートの構成に従う
- **書式（図記法・リンク・章番号・TODO 表記等）は [`docs-style.md`](docs-style.md) に従う** — 役割分担と書式を分けて管理する
