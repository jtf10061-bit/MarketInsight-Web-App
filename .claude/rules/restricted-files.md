# アクセス制約のあるファイルの取り扱い

Claude は以下のファイルへの **Read / Edit / Write、および Bash 経由の読み取り（`cat` / `head` / `tail` / `grep`）を実行できない**（[`.claude/settings.json`](../settings.json) の `permissions.deny`）。新規ファイル作成時もファイル名がパターンにマッチすると拒否されるため、**命名時にも注意**する。

## 対象ファイル

| パターン | 例 |
|---|---|
| `**/.env` `**/.env.local` `**/.env.development` `**/.env.staging` `**/.env.production` | 実値の入った環境変数ファイル |
| `**/*.pem` `**/*.key` | TLS / SSH 秘密鍵 |
| `**/credentials.json` | クラウド認証情報 |
| `**/*secret*` | ファイル名に "secret" を含む全ファイル |
| `~/.ssh/**` `~/.aws/**` | ホームディレクトリの認証情報 |

`.env.example` は **deny に含まれない**（テンプレファイルのため）。Claude が編集できる。

## 代替フロー

Claude は対象ファイルの実値を一切認識できない。**動作確認・テスト・デフォルト値の検証など、実値が関わる作業はすべてユーザー確認を必ず挟む**。設定ファイルのデフォルト値だけで判断・動作確認をしない。

### 値を書き込む必要があるとき

1. 書くべき内容をコードブロックで提示する
2. ユーザーに書き込みを依頼する（例: 「以下を `.env` に追記してください」）
3. 書き込み完了の確認をユーザーから得る

### 値を確認したいとき

1. **何を確認したいか・なぜ必要か** を明示する
2. ユーザーに値の提示を依頼する
3. 機密値そのものをコミット・ログ・PR 本文に残さない

## 環境変数を新規追加する作業

新しい環境変数を導入するときは：

1. **`.env.example` への追記は Claude が実施**（テンプレ更新）
2. **`.env` への反映はユーザーに依頼**（実値の書き込み）
3. 関連ドキュメント（`docs/architecture.md` の環境変数表など）も同時に更新する

## 新規ファイル名の検査

`.claude/rules/`, `docs/`, ソースコード等で新規ファイルを作成する前に、ファイル名が deny パターン（特に `**/*secret*`）にマッチしないか確認する。マッチする場合は別名にする。
